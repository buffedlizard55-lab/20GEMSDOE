## 2. Historical protocol specification (not current promotion evidence)

These are the rules written in the historical H20 file. Their chronology and execution are not independently demonstrated by this checkout. The same fixed spatial slice was evaluated for H20-1 and H20-5, so it was not an untouched single-shot vault across candidates.

1. **Spatial Dev / central slice partition (as originally specified):** each of the 4 geographic quadrants was partitioned into 4 spatial Development sub-blocks (`16` Dev sub-blocks total, stated `80.0%` of footprint = `4,133,899` pixels) and `1` central holdout strip (`4` strips total, stated `20.0%` = `1,033,474` pixels). The “Vault” name does not establish independence.
2. **Multiple-comparisons rule (as originally specified):** the file states Holm-Bonferroni step-down FWER ($\alpha = 0.05$) and Benjamini-Hochberg step-up FDR ($q = 0.05$) across the 16 development sub-blocks; this audit does not reproduce the analyses.
3. **Per-candidate reuse limit (as originally specified):** each candidate was allowed at most one evaluation on the slice. This does not make the slice single-shot overall: stored records show two candidates evaluated on that same slice.
4. **Current disposition:** none of these historical statements establishes hidden-fault performance, independent validation, or a current submission recommendation.
